## 1. 产品目标与范围

**目标：** 把 Osborn PA 的非知识库业务能力做成独立、可复制安装的飞书产品。先供自己公司多人使用，再交付其他企业并收费。页面、数据和运行由飞书平台承载；接受合理平台费用；不部署、不维护服务器、数据库、缓存或常驻服务。

**阶段顺序（不可调换）：**

| 阶段 | 内容 | 进入条件 |
| --- | --- | --- |
| 一期 | 全新独立产品：三入口、两套评分、工作台排程、多人权限、空白实例安装 | 无 |
| 二期 | 连接现有公司的需求管理、AI 项目管理两套多维表格 | 一期独立产品 Go |
| 三期 | AI 操作入口扩展、Agent 之间的日程协作 | 一期契约稳定；二期不阻塞三期设计，但不抢占一期 |

**一期不得依赖**旧公司的表、记录、成员或任何固定资源标识。

**非目标：** 知识库、采集插件、PA Cloud、Obsidian 知识架构；自建任何基础设施；原生日历双向同步；未核实的市场收费承诺。

## 2. 用户角色与使用流程

| 角色 | 主要任务 | 主要入口 |
| --- | --- | --- |
| 执行成员 | 整理自己的目标，把目标排进时间，改期、取消、完成 | 工作台、目标中心 |
| 项目负责人 | 评估项目投入优先级（要事为先），维护相关人与复盘，查看项目目标 | 项目中心 |
| 团队负责人 | 看团队目标与项目分布，周计划／复盘 | 目标中心、项目中心 |
| 实例管理员 | 安装、成员与角色、升级、故障处理 | 管理页（应用模式内，仅管理员） |
| 访客 | 只读被明确共享的非敏感内容 | 受限页面 |

**核心流程（工作台）：** 打开工作台 → 左侧本周日历，右侧“目标看板／轻重缓急”两种视图（同一份记录）→ 把目标拖到某天某时段 → 立即出现“保存中”占位 → 回执：已保存／已存在／冲突／被拒绝／待确认 → 目标仍在目标列表 → 可以在日历内拖动改期、点击完成或取消。键盘与移动端用“安排…”按钮填写时间完成同一件事。

## 3. 架构决策

### ADR-1 一个核心 Base，多张关联表 **[设计]**
项目、目标任务、成员、时间块、相关人、复盘、重复系列、实例设置、操作记录同在一个 Base。理由：原生关联、统一成员、单一权限面、复制与升级只处理一个容器。替代方案（两／三个 Base）需要跨 Base 同步、工作台跨源读取、权限和版本多处维护，当前无收益。唯一会推翻此决策的需求是“个人目标对企业管理员也不可见”，届时需要每人独立空间，由用户决定。

### ADR-2 三个入口 = 应用模式中的三个页面 **[待验证]**
目标中心（看板视图＋轻重缓急排序视图，读同一表）、项目中心（项目列表＋评分解释＋相关人＋复盘）、工作台（插件组件或托管页面）。应用模式提供独立角色、页面权限与行列数据权限（依版本）。普通成员不授予源 Base 访问，否则应用内权限可被绕过（审计 PLAT-07）。

### ADR-3 工作台承载：按顺序验证三条路线，不预设结论 **[待验证][待决定 D-2]**

| 路线 | 做法 | 托管 | 写入保证 | 主要风险 |
| --- | --- | --- | --- | --- |
| H1（首选验证） | 工作台作为应用模式“插件组件”，静态包发布到妙搭 HTML 托管，组件服务地址指向该地址；数据经 Base JS SDK 以查看者身份读写 | 飞书（妙搭） | SDK 创建无幂等参数；更新无 CAS | 能否被嵌入（CSP／frame）；自定义插件是否对其他成员可见；SDK 在插件组件中的能力 |
| H2（备选） | 妙搭全栈应用做工作台页面；后端用应用身份调 Base OpenAPI，创建带 `client_token` | 飞书（妙搭） | 创建幂等 **[已验证]**；更新仍无 CAS | 应用身份绕过 Base 权限，必须由 `policy.js` 先鉴权；妙搭计费与访问范围未知；工作台不在 Base 内 |
| H3（降级） | 纯应用模式原生页面＋“安排…”表单 | 飞书 | 同 H1 | 没有跨面板拖拽，属于核心交互降级，**必须用户批准** |
| H0（不采用） | 插件托管在 Vercel／Cloudflare 等 | 第三方 | — | 违反“不自建托管”约束；仅在用户明确同意时考虑 |

H1 与 H2 共用同一个前端（`packages/workbench`）与同一规则包（`packages/rules`），差别只在存储端口。

### ADR-4 业务规则单一来源 **[已实现]**
`packages/rules` 是评分、周期、重复、权限、命令合同的唯一语义来源；`fixtures/` 是对账基准。飞书公式、插件、CLI、未来 Agent 都必须通过同一组 fixture。旧仓库 JS 只作为测试 oracle，不在飞书运行。

### ADR-5 写入合同与能力声明 **[已实现（合同）][待验证（飞书端口）]**
所有写入经命令层（`commands.js`）：校验 → 权限 → 存储端口。端口必须声明两项能力：`atomicCreate`（同 operation_key 只产生一条）与 `conditionalUpdate`（过期 revision 被拒）。内存端口两项都提供；飞书端口按实测结果声明，UI 依声明显示保证级别。命令层自己不做“先查后写”。

### ADR-6 Base 时间块是一期时间权威 **[设计]**
飞书原生日历一期不接入（D-7）。如未来接入，仅单向投影，Base 为准。

### ADR-7 不引入自维护基础设施 **[设计]**
不建数据库、缓存、队列、锁服务、常驻进程。妙搭若采用，属于飞书托管，计费单列；它的应用数据库**不作为业务权威**（业务数据在 Base）。

## 5. 数据模型

完整逻辑字段字典：`packages/schema/manifest.json`（含类型、默认值、选项、所属配置 F0／F1）。以下只列语义规则。

### 5.1 表与关联

```text
实例设置（管理员）
成员 ── user 字段 → 飞书账号（一条成员 = 一个账号）
项目 1 ─< 目标任务（0..1 个项目）
项目 1 ─< 相关人、复盘
目标任务 1 ─< 时间块（独立时间块可无目标）
目标任务 ─ parent_goal → 目标任务（不成环，原生约束未证实，需命令层校验）
重复系列 1 ─< 时间块（occurrence_key 稳定）
操作记录（管理员只读）
```

### 5.2 标识规则
- `business_id`：新记录生成 UUID，建立后不可改；跨实例引用一律 `(instance_id, business_id)`。
- 飞书 record_id 只用于当前实例内链接，不进外部契约。
- 合成样例带 `sample_key`，新实例安装时重新生成 business_id；清理只按 `sample_key`。
- `operation_key`：每个写入意图一个；同一意图的重试复用同一键。拖拽时在落下时生成，表单在打开时生成。OpenAPI 写入的 `client_token` 由 operation_key 派生（UUIDv4 格式）。

### 5.3 状态机（不变量）

| 实体 | 动作 | 写入 | 禁止的副作用 |
| --- | --- | --- | --- |
| 项目 | 归档 | `attention_state=archived`（冷却 25） | 不完成目标、不删时间块 |
| 项目 | 停放 | `attention_state=parked`（冷却 10） | — |
| 目标 | 完成 | `status=done`，首次写 `first_completed_at`，每次写 `completed_at` | 不归档、不取消未来时间块（D-1 待定） |
| 目标 | 重开 | `status` 回非完成，清 `completed_at`，保留 `first_completed_at` | 不恢复已取消块 |
| 目标 | 归档 | `archived=true`，不可再安排 | 不删除历史块；未来块进入“待处理”清单（D-1 待定） |
| 目标 | 安排 | 新建时间块并关联 | 不改目标任何字段（D-1 待定） |
| 时间块 | 改期 | 新 start/end，revision+1 | 不改目标 |
| 时间块 | 完成 | `state=done` | 不完成目标（D-1 待定） |
| 时间块 | 取消 | `state=cancelled`（墓碑，保留） | 取消后不能原地恢复；“恢复”= 新建块 |

## 6. 两套评分 **[已实现（规则层）][待验证（飞书公式）]**

两套规则独立，不合并成泛化优先级。实现：`packages/rules/src/priority.js`；样例：`fixtures/scoring-golden.json`。

**共同：** `C(x)` = 转数值，非有限值取 0，四舍五入，限制 0–100。象限：重要性 ≥50 为重要，紧急性 ≥50 为紧急。等级：有效象限为重要且紧急或分数 ≥82 → P0；≥64 → P1；≥42 → P2；否则 P3。

**项目（要事为先，project-priority@1）：**
```text
D 截止压力：无／非法 0；已过 34；当天 30；≤3 天 24；≤7 天 16；≤14 天 9；≤30 天 4；否则 0
R 复盘逾期：逾期天数 ×3，上限 18
单人热度 = round(C(影响力,默认40)/100×10) + (blocked 16 / neutral 6 / 其他 0) + (触达已过 12 / 2 天内 8 / 其他 0)
H = min(28, Σ单人热度)
K 冷却：parked 10 / archived 25
动态紧急性 U = C(C(人工紧急性) + D + R + H − K)
分数 S = C(0.62×C(人工重要性) + 0.28×U + 0.10×H)
有效象限 = 人工固定象限 ?? 由(重要性, U)推导；有效等级 = 人工固定等级 ?? 由(S, 有效象限)推导
排序：S ↓、重要性 ↓、标题（中文排序）
```
**目标（轻重缓急，goal-priority@1）：** 默认 50／35；`T = C(0.62×重要性 + 0.38×紧急性)`；象限用人工紧急性；不叠加任何项目压力。排序：等级 ↓、分数 ↓、重要性 ↓、标题。

**日期：** 所有日期按 Asia/Shanghai 日历日计算；飞书日期单元格（毫秒）先换算为上海日期（与旧实现的差异见审计 RULE-02）。

**样例（节选，完整 40 余例见 fixture）：**

| 用例 | 输入 | 预期 |
| --- | --- | --- |
| A01 | 目标 50/35 | 44，重要不紧急，P2 |
| A02 | 目标 50/50 | 50，重要紧急，P0 |
| A04 | 项目 80/20 | U20，S55，P2 |
| A05 | 项目 80/20，今天截止 | D30，U50，S64，重要紧急，P0 |
| A06 | 项目 80/20，一人影响力100、blocked、触达已过 | 单人 38→H28，U48，S66，P1 |
| A10 | 项目 10/10，固定象限重要紧急 | S9，P0；若再固定等级 P3 → P3 |
| A13 | 项目 80/40，active／parked／archived | U 40/30/15，S 61/58/54 |
| Q01 | 截止 11-02，now 11-01 23:59:59／11-02 00:00:00 | 压力 24／30 |
| R03 | 截止为毫秒时间戳（上海 11-02 00:00） | 压力 30（旧实现为 0） |

**飞书实现策略：** 先尝试纯公式（相关人单行热度公式 → 项目汇总求和 → 截断），用 fixture 逐字段对账。做不到或刷新不可靠时，由受控执行者写 `score_snapshot`（全部中间量＋规则版本＋截至时间），界面显示“评分截至 …”。公式错误时显示“不可用”，不能显示 0 分。

**输入负担：** 新建项目默认 50/35；人工固定象限或等级必须填写理由（`pin_reason`）。

## 7. 周期迁移 **[已实现（规则层）]**

实现：`period-shift.js`。每天：明日→今日；周一：本周→今日，然后下周→本周；每月 1 日：本月→本周，然后下月→本月。每条规则基于上一步结果，单日最多前移一档（周一恰逢 1 日时，本月目标停在本周，下周一再进今日）。已完成、已归档不迁移。

幂等与恢复：每目标保存 `last_shift_date`；重跑同一天无变化；停机后逐日重放，最多 31 天，超过进入人工确认；每条更新带计划时的 revision，执行时若记录已被人改动则跳过并记冲突（飞书更新无 CAS，执行端只能“读-比-写-读回”，见 §10）。新目标首次只锚定日期不移动。

执行者 **[待验证]**：首选自动化每日 00:05（额度：免费／标准版 200 次／月共享）；或工作台打开时由当日首个访问者触发（无额度消耗，但依赖有人打开）。决策见 D-6。

## 8. 工作台交互规格

### 8.1 三种交互（互不替代）

| 交互 | 触发 | 命令 | 来源字段 |
| --- | --- | --- | --- |
| 跨面板拖入 | 目标卡片拖到日历时间格（30 分钟对齐，默认 1 小时） | `scheduleGoal` | `workbench_drag` |
| 日历内拖动 | 已有时间块拖到新时间格（保持时长） | `rescheduleBlock` | — |
| 点击填写 | 目标卡片“安排…”→ 日期、开始、结束 | `scheduleGoal` | `workbench_form` |

第三种是键盘、读屏和移动端的必备路径，**不能静默替代**第一种。若平台无法实现第一种，按 ADR-3 报告证据并由用户决定。

### 8.2 保存状态与恢复

| 回执 | 用户看到 | 系统状态 | 下一步 |
| --- | --- | --- | --- |
| 保存中 | 日历上半透明占位 | 请求在途 | — |
| 已保存（committed） | 实块出现 | 写入完成 | — |
| 已存在（duplicate） | 实块（不新增） | 同键早已写入 | — |
| 冲突（conflict） | “他人已修改，未覆盖”，显示当前值 | 未写 | 刷新后重新操作 |
| 被拒绝（rejected） | 原因（时间无效、无权限、目标已归档…） | 未写 | 修正后重试 |
| 待确认（unknown） | “结果待确认”，占位保留，提供“对账”“同键重试” | 可能已写 | 对账或同键重试，绝不换新键重建 |

本地原型已在真实浏览器演示：跨面板拖入、刷新读回、响应丢失→待确认→同键重试返回“已存在”且只有一条、另一标签页修改后本页取消→冲突且未覆盖。

### 8.3 其他状态
空目标（区分“无可见目标”与“加载失败”）；无权限（不显示为空闲）；他人时间块只显示“忙碌”；长标题省略；标题与备注一律按文本渲染，不作为 HTML 或指令。

## 9. 时间语义与重复 **[已实现（规则层）]**

- 时间块存 `start_at`／`end_at`（毫秒）＋ `timezone`；全天块用 `all_day_start`／`all_day_end`（日期），二者互斥。`end > start`，单块最长 31 天。
- 跨日块：时长保留，网格裁剪显示并标“+1”。
- 重复系列（`recurrence.js`）：日／周，间隔固定 1；滚动生成窗口默认 8 周（D-6）；发生键 = 系列＋代际＋原始日期，改期不变；取消例外与墓碑优先，重建不复活。
- 修改范围：**本次** = 例外（moved／cancelled）；**本次及后续** = 旧代际在切点退休，新代际从切点生成，已完成历史不改，未完成的旧项标记被取代，同频率的例外迁移到新代际，频率改变时列出冲突交用户决定；**全部** = 修改系列并重算未完成的未来项，历史保留。
- 这是相对旧系统的新能力（旧系统只有删除范围），见审计 RULE-06。

## 10. 写入一致性：每条路径的真实保证

| 路径 | 创建 | 更新 | 结果未知时 |
| --- | --- | --- | --- |
| OpenAPI（H2、CLI、Agent） | `client_token` 幂等 **[已验证]**，限流 1254290 后同令牌重试 | 无 CAS **[已验证]**：读-比-写-读回，检测到 revision 跳变即报冲突 | 同令牌重试 |
| Base JS SDK（H1） | 无幂等参数：落盘前按 operation_key 查询；在途请求本页加锁；事后按 operation_key 去重（保留最早一条，其余标取消并记录） | 同上 | 按 operation_key 查询后决定 |
| 原生编辑（源表直接改） | 无 operation_key | 无检查 | — ；因此普通成员不开放源表编辑 |

**残余风险（需 D-3 接受）：** H1 下同一意图在“请求在途且页面刷新后重试”的窗口内可能短暂出现两条，去重会收敛；任何路线下两人同时改同一时间块都可能后写覆盖，缓解是“只有负责人能改自己的块”，写后读回发现跳变时提示。

## 11. 权限

### 11.1 矩阵（产品语义，需平台实测）

| 对象／动作 | 实例管理员 | 项目负责人 | 成员 | 访客 |
| --- | --- | --- | --- | --- |
| 源 Base | 管理 | 无（只通过应用） | 无 | 无 |
| 项目读 | 全部 | 本人负责与参与的项目 | 参与项目 | 指定项目只读 |
| 项目评分与固定 | 改 | 本项目可改并写理由 | 只读 | 无 |
| 目标读 | 全部（含 private） | 本项目非私有目标 | 自己负责／参与的，及参与项目的非私有目标 | 显式共享的非私有目标 |
| 目标编辑 | 全部 | 本项目 | 自己负责／参与的 | 无 |
| 安排目标 | 是 | 本项目目标 | 自己能编辑的目标 | 无 |
| 时间块编辑 | 全部 | 仅自己的 | 仅自己的 | 无 |
| 他人时间块 | 详情 | 仅忙闲 | 仅忙闲 | 无 |
| 成员与角色、设置、操作记录 | 管理 | 无 | 无 | 无 |

`private` = 对其他成员与访客不可见；**实例管理员可见**（单 Base 无法承诺对管理员不可见）。实现见 `policy.js`。

### 11.2 传播规则 **[设计]**
- 私有目标默认不允许关联到项目汇总（计数、完成率），或汇总只按查看者可见子集计算——二选一，首期选“不关联”。
- 项目评分解释与其相关人输入同一权限范围。
- AI 摘要（可选、默认关闭）只取查看者可见字段，结果不写入更公开的字段。
- 撤权后：插件每次写前重新取权限；缓存按 (实例, 身份, 权限版本) 隔离。
- CLI／Agent 默认用户身份；bot／应用身份写入只限安装与运维。
- 行级权限要求专业版及以上（审计 REQ-03）。

## 12. 初始化、安装、版本、升级、回滚

### 12.1 安装产物
`packages/schema/manifest.json`（逻辑结构）＋ 清单 hash ＋ 规则版本 ＋ fixture 版本 ＋ 工作台构建版本。实例安装记录（保存在实例设置表）：instance_id、物理表／字段 ID 映射、每步状态、清单 hash。

### 12.2 安装状态机
`new → schema_created → relations_bound → rules_installed → roles_configured → app_pages_ready → workbench_registered → sample_checked → ready`。任一步失败记 `failed_at(step)` 与已建资源；重跑先核对再继续，不重复建表；未到 `ready` 不向成员开放。

### 12.3 安装步骤（第二实例）
1. 管理员在新租户创建空 Base（或 CLI `+base-create`），记录 instance_id。
2. 安装器按清单建表、字段、关联（幂等：按逻辑名查找已存在资源）**[设计，脚本待写]**。
3. 写入公式字段并用 fixture 对账。
4. 开启高级权限、创建角色。
5. 应用模式：建三入口页面（无 CLI 复制，按手册操作或待新版 CLI 验证）。
6. 工作台：登记插件组件服务地址（H1）或妙搭应用访问范围（H2）。
7. 成员映射：每个成员一条记录、一个账号；不导入开发者身份。
8. 可选合成样例 → 健康检查 → `ready`。通知、AI、日历投影保持关闭。

### 12.4 升级与回滚
升级前比对受管字段与公式；客户改动过的受管项 → `blocked_upgrade`，保持旧版本。工作台前端版本与清单 schema 版本绑定，不兼容时只读。回滚：停止可选自动化 → 导出数据 → 恢复上一兼容前端／配置 → 健康检查；schema 不可回退时保持只读与导出，不删数据。

## 16. 三期：Agent 协作（延期，保留契约方向）

CLI 是操作入口，不是协商协议或常驻服务。三期契约沿用命令层：`query_authorized_availability`（只返回忙闲区间与完整性，不返回标题；查不到的日历标 unknown，不当空闲）、`propose_slots`、`hold_slot`（能否原子暂占待验证）、`confirm_schedule`（各方各自授权）、`reschedule`／`cancel_schedule`（带 expected_revision 与 operation_key）、`query_receipt`。状态：draft → proposed → held → confirmations_pending → confirmed／conflict／expired／rejected／partial。对方 Agent 的自然语言不是授权凭证。一期只保证稳定 ID、operation_key、回执与权限边界。

## 17. 二期集成边界（延期）

一期 Go 之后才做。原则：现有需求 Base 继续为需求权威；“已采纳需求 → 项目／目标”显式登记映射；不按名称自动匹配；来源优先级（P0–P3、高／中／低）原样保存，不反推重要性／紧急性；旧成员表一条多账号的情况先拆分映射再接入；集成断开时一期产品照常运行。旧模板结构盘点保留在本地历史材料中（含内部标识，不公开）。
