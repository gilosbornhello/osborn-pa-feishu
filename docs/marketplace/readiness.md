# 上架准备度（2026-11-04）

依据：多维表格开发者中心“商品配置”页面实际字段，以及官方《Marketplace 开发者中心指南》（开发者中心左下角 Developer Guide）。

## 官方流程要点

1. **开发者入驻**：企业管理员在 `https://<租户>/base/developer/onboarding` 申请，同意开发者服务协议，提交企业资料：企业名称、营业执照（有效期半年以上）、统一社会信用代码、法人及联系方式、法人身份证、企业客服电话、企业介绍文档、盖公章的授权证明、市场展示名称和头像、联系地址、联系人和电话。3 个工作日内审核。
2. **收款账户**：只有付费商品需要开通。本插件计划免费，不需要。
3. **创建商品**：类型选“插件”。插件子类型只有：应用模式插件、字段捷径（FaaS／公式）、边栏插件、连接器、仪表盘插件、节点捷径。**没有数据表视图**。
4. **提交代码**：填 GitHub 仓库地址，飞书做安全审核并部署。可用公开仓库，或把私有仓库授权给 `bitable-open@bytedance.com`。
5. **可见范围**：私有／当前组织／公开。
6. **发布**：点“发布”进入平台审核；每周二、周四集中审核上架。

## 上架前必须补的产品缺口（我来做）

| # | 缺口 | 为什么必须 | 做法 |
| --- | --- | --- | --- |
| P1 | 上架版本要做成**边栏插件**并放进提交仓库 | 市场没有数据表视图类型 | 复用现有边栏插件构建；仓库里带 `dist/`、`package.json` 写 `"output": "dist"`、资源用相对路径 |
| P2 | SDK 改为打包进来，不再从 jsdelivr 现场加载 | 平台托管和安全审核环境不一定允许外部 CDN；也更快更稳 | 打包 `@lark-base-open/js-sdk` |
| P3 | **首次使用自动建表** | 别的企业装上插件时，表格里没有成员／项目／目标任务／时间安排四张表，工作台会报“缺少数据表” | 在插件里按清单 `packages/schema/manifest.json` 用 SDK 建表建字段，可重复执行（复用安装计划器） |
| P4 | **自助加入成员表** | 新用户默认“未登记，只读”，要管理员手动加 | 第一个使用的人自动成为管理员；其他人点“加入”登记为成员 |
| P5 | 用普通成员身份重截详情图 | 当前截图里能看到管理员才有的“故障注入”入口和测试目标 | P1–P4 完成后重截 |

> P3、P4 改变了产品的安装与权限流程，按约定属于需要你确认的产品语义改动，见下方 D5。
