# 托管工作台测试用例（给自动化测试机器人）

> 对象：妙搭托管的工作台原型 `<HOSTED_URL>/workbench` 与只读探针 `<HOSTED_URL>/probe`（真实地址不入库，向项目负责人索取）。
> 数据：全部为合成样例，保存在**测试浏览器自己的本地存储**，不连接飞书数据，不会影响任何人。
> 不需要登录。每个用例开始前，展开顶部“故障注入”，点“重置合成数据”，除非用例另有说明。

## 机器人须知

- 拖拽是 **HTML5 原生拖放**（`dragstart/dragover/drop` + `DataTransfer`）。只发鼠标移动事件的工具可能拖不动；Playwright 请用 `locator.dragTo()` 或派发带 `DataTransfer` 的拖放事件。
- 时间格：每天 07:00–22:00，每格 30 分钟；拖入默认时长 60 分钟。周起始为周一。
- 页面时区按 Asia/Shanghai 显示。
- 回执在页面下方“保存回执”区，每次保存一行，状态文字为：已保存／已存在（未重复创建）／版本冲突，未覆盖／被拒绝／结果待确认／确认未保存。
- 每个用例记录：通过/失败、截图、控制台错误、失败时的回执文字。

## A. 托管与加载

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| A1 | 无登录状态打开 `<HOSTED_URL>/workbench` | 不跳转登录页；显示“工作台”、身份下拉、左侧一周日历、右侧目标列表 |
| A2 | 打开开发者工具网络面板后刷新 | 页面 HTML 之外只加载 `workbench.css`、`workbench.js` 两个文件；`workbench.js` 先 302 跳到飞书 CDN 的签名地址是正常的，最终状态均 200；无 403/404 |
| A3 | 查看控制台 | 无报错 |
| A4 | 打开 `<HOSTED_URL>/probe` | 显示“宿主环境探针（只读）”；“SDK 加载”一行为成功；“是否在 iframe 内”为 false |
| A5 | 打开 `<HOSTED_URL>/`（结尾带斜杠） | 显示两个链接“工作台原型”“宿主环境探针”，点击均可打开 |

## B. 三种交互（不得互相替代）

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| B1 跨面板拖入 | 身份“林晓（成员）”。把右侧“完成试点方案初稿”拖到日历周三 09:00 格 | 先出现“保存中”占位，随后变为 09:00–10:00 的时间块；回执“已保存”，来源为拖入；右侧该目标**仍在列表中、未变化** |
| B2 同一目标再拖一次 | 接 B1，把同一目标拖到周四 14:00 | 新增第二个时间块；原周三块不变；目标仍在 |
| B3 日历内拖动已有块 | 把 B1 的周三块拖到周五 11:00 | 该块移到周五 11:00–12:00，时长不变；不新增块；回执为改期且“已保存” |
| B4 点击后填写时间 | 点目标“约三位种子用户访谈”右侧“安排…”，填日期、开始、结束后点“保存” | 生成对应时间块；回执“已保存”，来源为表单安排 |
| B5 表单校验 | 在“安排…”里把结束时间设为早于开始，点“保存” | 不生成块；提示未保存原因 |
| B6 表单连点 | 打开“安排…”，快速点两次“保存” | 只生成 **1** 个块；回执为一条“已保存”，或“已保存”＋“已存在（未重复创建）” |
| B7 取消 | 打开“安排…”后点“取消” | 不生成块、不产生回执 |

## C. 可靠性（故障注入）

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| C1 响应丢失 | 勾选“下一次保存响应丢失”，拖一个目标进日历 | 回执“结果待确认”，占位保留，并出现“对账”“用同一键重试”；数据其实已写入 |
| C2 同键重试 | 接 C1，点“用同一键重试” | 回执“已存在（未重复创建）”；该目标在该时段只有 **1** 个块；原回执上的两个按钮变为不可点 |
| C3 对账（已写入） | 重复 C1，改点“对账” | 回执“已存在（未重复创建）”，表示已找到该操作；不新增块；占位消失 |
| C4 版本冲突（页内模拟） | 点“模拟另一标签页改动首个安排”，再点击首个时间块，在弹出的菜单中选“取消安排” | 回执“版本冲突，未覆盖”；该块保持另一处修改后的状态，未被本页覆盖 |
| C5 刷新读回 | 做完 B1–B4 后点“刷新读回”，再按浏览器刷新 | 所有块位置、时长不变；无重复 |
| C6 真实两个标签页 | 同一浏览器开两个工作台标签页 T1、T2。T1 点首个时间块打开菜单先不选；T2 把该块拖到别的时间；回到 T1 点“取消安排” | T1 回执“版本冲突，未覆盖”；该块保持 T2 改后的时间，状态不是“已取消”；T1 日历自动显示 T2 的新位置 |
| C7 提交前失败 | 勾选“下一次保存在提交前失败”，拖一个目标进日历，再点“对账” | 先回执“结果待确认（request failed before commit）”；对账后回执“确认未保存”；块数不变，占位消失 |
| C8 故障不串到别的操作 | 身份林晓，勾选“下一次保存响应丢失”，拖周航的“评审定价假设”（会被拒绝），再在日历内拖动一个自己的块 | 第一次“被拒绝”；第二次改期回执“已保存”，不是“结果待确认”（故障只对下一次操作有效，不论结果如何都会清掉） |
| C9 改期/完成也能同键重试 | 勾选“下一次保存响应丢失”，在日历内拖动一个块，点该回执上的“用同一键重试” | 回执“已存在（未重复创建）”；块只移动一次 |

## 已知观察（不判失败）

- G3／G4 需要真实鼠标拖拽：自动化浏览器（扩展或 CDP）发出的拖拽不触发 HTML5 拖放事件，机器人只能跑 G2、G5、G6 和表单安排。
- 直接在表里改时间不会增加 revision；工作台写入时另比对开始／结束／状态，手工改过的块会得到“版本冲突”（2026-11-04 起）。

- G1 必须在插件面板内运行；直接在浏览器或飞书内置浏览器打开时，首行“运行环境”显示“不在 iframe 内”，随后 `getTableMetaList` 超时，这是预期结果。

- 同一目标可以多次拖入，每次生成新块（B2）；拖入时不提示“已排过”。
- 成员能看到同项目他人的目标，但拖入后才得到“被拒绝”，界面不提前标示。
- 实例管理员能看到私有目标（审计项 P-02：单个 Base 无法对管理员隐藏）。
- 刷新后“保存回执”清空，数据不变。
- 手机宽度：目标列表在日历上方，提示文案仍写“左侧”。
