### 2026-11-03 补记：插件内要求 cookies → 页面改为公开
- 现象：把妙搭页面作为自定义插件加入测试 Base 后，插件内提示需要允许 cookies（桌面客户端与浏览器都出现）。判断：页面设为“需登录”，在多维表格插件框架中属于跨站嵌入，登录 cookie 被当作第三方 cookie 拦截。
- 处理（用户在对话中同意）：访问范围改为**公开、不要求登录**（`scope=All`，`require_login=false`）。理由：页面只含静态代码（与公开仓库相同）、不含数据；数据读写走 Base JS SDK，以使用者自己的 Base 权限进行。代价：任何拿到链接的人都能打开空壳页面与合成样例。不应要求每个使用者修改浏览器 cookie 设置。
- 同时发现并修复两个妙搭托管特性（`tools/build-hosted.mjs`）：
  - `x.html` 被重定向到无扩展名、无结尾斜杠的地址，子目录页面的相对路径会错一级 → 页面放到站点根目录（`/workbench`、`/probe`）。
  - 脚本被 302 到带签名的 CDN 地址，ES 模块的相对 import 落到无签名地址返回 403 → 新增零依赖打包器 `tools/bundle-esm.mjs`（只支持本仓库用到的导入导出形式，遇到其他形式直接报错）及 3 项测试，工作台以单文件发布。
- 验证（内置浏览器、未登录）：`/workbench` 正常渲染，只请求 `workbench.css`、`workbench.js` 两个资源且均 200，7 张目标卡可拖；`/probe` 正常，SDK 从 jsDelivr 加载成功（不在多维表格内，读表不适用）。
- 仍待验证：在多维表格插件（桌面客户端与浏览器）中重新加载 `/probe`，看 SDK 能否读到当前 Base 的表。

### 2026-11-03 补记：第一轮机器人测试（托管页，无头 Chromium）
- 范围：`docs/test/hosted-workbench-cases.md` 的 A–E 组，共 28 条（文档原写 30 条，实为 28 条）。结果：通过 22，失败 3，F 组 3 条因无飞书账号跳过。F 组（插件内能否读到测试 Base 的表）**仍未验证**。
- 已确认的缺陷与处理：
  - **多标签页丢失更新（高）**：每个标签页把整份数据读进内存，再整份写回 localStorage；未刷新的标签页会悄悄覆盖另一标签页的改期。页内“模拟另一标签页”按钮改的是本页内存，所以原用例没测出来。修复：内存端口新增可选共享存储 `store`，每次调用先重读、写入与版本检查在同一同步步骤内完成；页面监听 `storage` 事件自动刷新。新增单测“两个标签页共享存储”。本地用两个真实标签页复测：旧标签页得到“版本冲突，未覆盖”，块保持新时间。
  - **故障标记串到别的操作（中）**：“下一次保存响应丢失”在操作进存储层前被拒绝时没有清掉。修复：所有命令统一走 `runCommand`，故障只对下一次操作有效，无论结果如何都清掉。
  - **改期／完成／取消安排的“用同一键重试”无反应（中）**：没有传重试回调。修复同上，重试重发同一操作键；结果确定后原回执上的按钮变为不可点。
  - **无法测到“确认未保存”（低）**：新增故障“下一次保存在提交前失败”及单测；对账得到“确认未保存”。
  - A2 判失败是用例写法不清：`workbench.js` 302 到签名 CDN 再 200 是预期行为。已改写用例。
- 用例：新增 C6–C9（真实两个标签页、提交前失败、故障不串、改期同键重试），补“已知观察”一节。
- 测试 87 项全部通过；重新发布到妙搭，访问范围仍为公开、不要求登录。
- 意义：这些缺陷都在本地参考端口和页面逻辑里。Base SDK 端口要达到同样的保证（写前比对版本、同键幂等），不能整份覆盖写回。
